# ADR-0011：只接入有协议证据的视频互动写操作

- 状态：已接受，稍后观看与新建播放列表仍待接口证据
- 日期：2026-07-24

## 背景

统一观看页原先只有播放、收藏和下载，缺少产品架构要求的评分、播放列表、评论、实体互动和订阅。写接口如果猜错参数，可能把内容加入错误集合、产生重复写入或误导用户，因此必须把“页面上看起来可用”和“服务端协议已验证”区分开。

## 决策

### 已接入操作

- 视频喜欢/不喜欢：`action=rate`，`vote=5|0`；
- 标签、分类和艺术家关联投票：`action=rate`，附带对应 `{type}_id` 与 `vote=1|-1`；
- 加入已有播放列表：复用收藏协议，`fav_type=10` 与真实 `playlist_id`；
- 分类和艺术家订阅/取消订阅：`action=subscribe|unsubscribe` 与对应实体字段；
- 发表评论：使用 Dio `FormData.fromMap` 发送 multipart 表单，成功后重新加载详情；
- 收藏和下载继续沿用既有账号登录边界。

所有写操作：

1. 必须登录；
2. 防止按钮重复提交；
3. 显示进行中状态；
4. 将网络或服务端语义错误反馈给用户；
5. 不在本地伪造服务器收藏、订阅或评论状态。

### 详情解析

`VideoDetails` 新增：

- 评分票数；
- 带 ID、路径、类型和投票统计的 `VideoMetadataItem`；
- 评论总数与当前页面评论；
- 评论作者、成员路径、头像、时间和正文。

分类、标签和艺术家芯片可打开统一内容集合；点击后还可以在操作面板中投票，分类和艺术家可以订阅。订阅初始状态来自账号 `/my/subscriptions/`，读取失败时不猜当前状态。

### HTTP 200 语义错误

异步操作可能在 HTTP 200 响应中返回 `<error>`、`.generic-error` 或 `.field-error`。API 层统一识别这些结构并抛出 `ApiException`，防止页面错误显示成功。

### 明确延期

- 稍后观看写入：接口文档没有可靠的 `fav_type` 证据；
- 新建播放列表：创建表单字段和可能的 CSRF/可见性参数尚未完成验证；
- 评论投票与评论分页：当前首版展示详情页已返回的评论，后续按真实分页协议扩展。

## 验证

- 脱敏 HTML fixture 验证元数据实体、评分票数和评论解析；
- 请求适配器验证评分、实体投票、播放列表、订阅和 multipart 评论协议；
- Parser 测试验证 HTTP 200 语义错误；
- Widget 测试验证详情页评分与评论按钮真实调用 API，并在评论后刷新详情；
- Widget 测试使用下载平台替身，避免在测试中误构造原生后台下载插件；
- Flutter 静态分析和全部 40 条测试通过。
