# ADR-0014：账号资料、外部表单、诊断与更新源

- 状态：已接受
- 日期：2026-07-24

## 背景

首版需要让“我的”真正承担身份、设置和支持入口，同时不能猜测网站表单协议、泄露登录凭据，或把尚未创建的 GitHub 仓库地址写死在客户端中。

## 决策

- 从公开成员资料页已经验证的 `.channel_logo` 区域解析显示名、头像和订阅数，并写入现有账号缓存表；
- 编辑资料、修改邮箱、修改密码和反馈使用系统浏览器打开官方 HTTPS 页面；反馈页面保留网站验证码流程，不在 App 内伪造无验证码提交；
- 诊断报告包含 App、Flutter 构建注入值、Dart、Android、数据库、下载摘要和设置，不包含 Cookie、密码、邮箱、用户 ID 值或设备标识符；
- 更新源通过 `FLULE34_UPDATE_API_URL` 和 `FLULE34_REPOSITORY_URL` 编译参数配置；未配置时明确显示开发构建状态；
- 更新检查支持稳定版与预发布版通道，解析 GitHub Releases JSON 并比较语义版本；
- App 只打开配置的发布页，不静默下载或安装 APK，发布包必须另行提供签名和 SHA256 校验信息；
- 运行时版本来自 `package_info_plus`，设备摘要来自 `device_info_plus`，外部 HTTPS 跳转使用 `url_launcher`。

## 后果

- 未提供编译参数的本地构建仍可正常使用，但 GitHub 与更新入口会显示“未配置”；
- 网站资料页结构变化可能导致显示名和头像退化为用户 ID，需要通过 Parser fixture 更新选择器；
- Flutter 版本、Git 提交和构建时间只有在 CI 注入后才会出现在诊断报告中。

## 验证

- Parser 测试覆盖成员资料字段；
- 设置测试覆盖更新通道持久化；
- 更新服务测试覆盖版本比较、稳定通道过滤和 APK 资产解析；
- 静态分析、全量测试和 Android APK 构建作为提交门禁。
