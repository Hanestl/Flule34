# ADR 0016：产品闭环、网络策略与可验证写操作

- 状态：已接受
- 日期：2026-07-25

## 背景

真机反馈暴露出原型在年龄门、主题、视频卡片和播放器上的关键体验偏差。与此同时，首页关注、卡片操作、网络播放策略、隐私设置和下载恢复必须从“页面占位”升级为真实行为。

## 决策

1. 年龄确认先在内存中过门，再异步持久化；失败必须可见提示。
2. 主题只提供浅色、深色和跟随系统；默认跟随系统，深色使用中性灰。
3. 列表解析以网站当前 `.time`、`.thumb_title`、`.added`、`.rating` 和 `.views` 结构为准，并用脱敏 fixture 回归。
4. 视频详情与播放器合并；从卡片进入即播放，全屏复用同一控制器并始终保持视频原比例。
5. 播放清晰度由用户默认值、网络策略和当前网络类型共同决定；常亮只在实际播放时开启。
6. 首页关注频道最多聚合八个账号订阅源并交错去重，避免单一来源垄断列表。
7. 下载并发通过 `background_downloader` 原生 holding queue 限制；401、403、404 类失败刷新详情令牌后重建任务。
8. 账号写操作只实现已有证据的收藏、评分、评论、评论投票、订阅和加入已有播放列表。稍后观看与新建播放列表在协议验证前保持禁用或明确说明，不猜测参数。
9. 项目主代码采用 Apache License 2.0，第三方依赖继续保留各自许可证。
10. 已登录请求遇到登录页重定向或 HTTP 401/403 时清除本地过期会话并要求重新登录，禁止把登录页解析为空媒体库或把失败写操作显示为成功。

## 结果

- 用户设置必须有实际消费者和回归测试，不保留无行为的开关。
- 网络类型只能用于策略选择，不能被当作互联网可用性的保证。
- 网站 HTML 或 JavaScript 结构变化时，先更新证据与 fixture，再修改写协议。
- Android 10–16 真机矩阵、正式签名和 GitHub 远程工作流仍是首次发布前的发布门禁。
