# ADR-0001：账户绑定的用户数据与下载隔离

- 状态：已接受
- 日期：2026-07-24

## 背景

收藏、稍后观看和观看历史如果允许匿名本地保存，用户登录后就会产生合并、覆盖、重复和冲突处理问题。下载文件虽然位于本机，也可能在多账号切换时泄露另一个账号的内容和观看行为。

## 决策

1. 收藏、稍后观看和播放列表以网站服务端账号数据为准。
2. 观看历史优先与网站账号同步；本地数据库只保存缓存、播放进度和待同步状态。
3. 所有本地用户数据必须以稳定的网站用户 ID 分区，不能只用当前 Session ID。
4. 下载任务、下载记录和下载文件均归属于发起下载的网站用户 ID。
5. 未登录用户不能创建持久化的收藏、稍后观看、观看历史或下载任务。
6. 退出登录后立即停止使用该账号凭据的网络任务，并隐藏该账号的媒体库数据。
7. 默认退出登录不删除已完成下载；同一用户重新登录后可以恢复显示。
8. 切换账号时不得自动合并数据，也不得向新账号展示旧账号的数据。
9. 用户可以在退出登录或设置页主动选择删除该账号在设备上的下载和缓存。

## 下载存储要求

- 默认使用 App 私有存储，不自动把成人内容暴露到系统相册或公共媒体目录。
- 导出到公共目录必须由用户对单个文件显式发起。
- 数据库记录至少包含用户 ID、视频 ID、清晰度、文件路径、字节进度、状态、错误、创建时间和完成时间。
- 开始或恢复下载前重新获取有效视频源，不能长期保存并盲目复用带时效令牌的 URL。
- 会话过期时任务进入“等待登录”状态，而不是无限重试或改用其他账号凭据。

## 后果

优点：

- 账户切换行为明确；
- 不需要设计高风险的匿名数据合并规则；
- 本地隐私边界清晰；
- 服务端数据和 App 状态更容易保持一致。

代价：

- 未登录用户无法使用媒体库和下载；
- 必须可靠解析并持久化稳定用户 ID；
- 下载调度器和本地数据库必须支持用户分区及会话过期状态。
