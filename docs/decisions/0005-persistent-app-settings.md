# ADR-0005：可测试且真实生效的 App 设置

- 状态：已接受
- 日期：2026-07-24

## 背景

原型中的“我的”页只有若干禁用占位项，既不能表达账号状态，也不能改变 App 行为。设置功能需要长期演进，同时不能让页面、播放器和下载器直接依赖平台插件。

## 决策

### 页面架构

“我的”作为身份与 App 管理中心，包含：

- 登录状态、稳定用户 ID 和账号隔离说明；
- 账号与安全；
- 外观、播放、内容、下载、隐私与数据；
- 帮助与反馈、关于和更新状态。

每组设置使用独立二级路由，不把所有控件堆叠在一级页面。

### 数据边界

- 网站账号身份继续由安全 Cookie 和稳定用户 ID 表示；
- App 偏好是设备级设置，不与网站账号同步；
- 密码不进入设置层，也不由 App 持久化；
- 接口尚未稳定提供的昵称和头像不伪造，后续通过独立资料解析能力补充。

### 持久化

- 使用 `shared_preferences 2.5.5` 的 `SharedPreferencesAsync`；
- 页面和业务层只依赖 `AppSettingsRepository`；
- Repository 通过 `AppSettingsStore` 抽象平台读写，测试使用内存实现；
- 所有键统一使用 `flule34.settings.*` 命名空间；
- 未知枚举值和错误数据类型回退到安全默认值，避免设置损坏阻断 App 启动。

### 当前真实生效的设置

- 跟随系统、深色和 OLED 纯黑主题；
- 默认播放清晰度、自动播放和循环播放；
- 视频卡片封面模糊；
- 下载前询问清晰度、默认下载清晰度和仅 Wi-Fi 下载。

清晰度规则优先解析分辨率数值；指定清晰度不存在时选择最接近的可用来源，相同距离优先较高清晰度。“自动”暂时选择最高可解析来源，待网络质量策略完成后再动态调整。

## 验证

- 设置默认值、持久化恢复和错误旧值回退测试；
- 清晰度选择规则测试；
- 下载任务仅 Wi-Fi 参数测试；
- “我的”到播放设置的路由回归测试；
- Flutter 静态分析和完整测试通过。

## 后续

1. 从真实登录页面可靠解析昵称和头像；
2. 将播放进度记忆与屏幕行为接入播放设置；
3. 建立隐藏标签、内容取向和预览网络策略；
4. 完成下载并发、文件保留、公共目录导出与清理；
5. 使用构建时版本信息替代关于页中的静态版本文本；
6. 接入帮助、诊断、GitHub Release 更新和开源许可清单。
