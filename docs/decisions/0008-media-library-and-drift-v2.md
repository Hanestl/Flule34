# ADR-0008：完整媒体库入口与 Drift v2 播放元数据

- 状态：已接受，订阅和媒体库写操作仍待扩展
- 日期：2026-07-24

## 背景

媒体库原先只有收藏和下载两个页签，无法承载产品架构中要求的继续观看、稍后观看、网站历史和播放列表。本地播放记录只有视频 ID 与毫秒进度，也不足以独立渲染继续观看卡片。

## 决策

### Drift v2

`playback_positions` 新增可空字段：

- `title`；
- `slug`；
- `thumbnail_url`；
- `duration_label`。

字段保持可空，使已有 v1 记录无需伪造元数据即可迁移。新播放器保存进度时写入当前 `VideoItem` 元数据。

迁移使用 `drift_dev make-migrations` 生成的 step-by-step helper，不维护另一套手写版本判断。schema v1 和 v2 快照都保存在 `drift_schemas/app_database/`。

迁移测试同时插入账号、播放进度和下载记录，验证 v1→v2 后：

- 原有字段和值不变；
- 新增元数据字段为 null；
- 下载记录和账号外键数据不丢失。

### 媒体库页面

登录后的媒体库使用手机友好的可横向滚动页签：

1. 继续观看；
2. 收藏；
3. 稍后观看；
4. 网站历史；
5. 播放列表；
6. 下载。

视频列表启用 KeepAlive，切换页签时尽量保留滚动位置和已加载数据。继续观看使用本地账号分区进度，网站历史使用 `/my/history/`，两者职责明确分离。

### 播放列表

- 新增 `PlaylistItem` 领域模型；
- 从账号播放列表 HTML 解析 ID、标题、路径、缩略图、视频数量和观看量；
- 播放列表详情使用根导航打开，不显示底部一级导航；
- 详情视频继续复用统一 `VideoFeed`。

## 验证

- Drift v1→v2 空库 schema 验证；
- Drift v1→v2 账号、进度和下载数据完整性验证；
- 继续观看元数据与账号隔离测试；
- 播放列表脱敏 HTML 解析测试；
- 稍后观看、历史和播放列表分页 URL 回归测试；
- Flutter 静态分析和全部 24 条测试通过。
